# Architecture decisions

No application architecture decisions have been accepted yet. Framework, storage and source compatibility choices belong to their discovery/setup tasks.

Write a short ADR for a significant choice that future contributors need to understand. Use the next available number, keep the decision focused, and link evidence and the relevant issue/spec. Do not create an ADR for every small implementation detail.

Copy this outline into `NNNN-short-title.md` when a real decision is proposed:

```markdown
# NNNN: Decision title

Status: Proposed
Date: YYYY-MM-DD
Related issue/spec: link

## Context
The concrete problem and constraints.

## Decision
The proposed choice and why it fits current needs.

## Alternatives
Viable alternatives and why they were not selected.

## Consequences
Trade-offs, limitations and follow-up work.

## Evidence
Source links, observations or measurements; distinguish assumptions.
```

Record owner approval before changing status to Accepted. Replace a changed accepted decision with a new ADR and link both using Superseded/Supersedes references; preserve the original rationale.
